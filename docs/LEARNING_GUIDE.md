# 把项目变成自己的学习证据

项目提供代码与工具，个人学习的证据来自你实际操作后写下的问题、结果与解释。

## 第一次运行

先用人工描述基线搜索一个物体，再准备模型索引，用同一句话运行真实图文检索。打开算法说明，找到图片编码、文本编码、归一化与排序对应的代码：`lab/engine.py` 和 `lab/retrieval.py`。

在笔记中用自己的话说明：两个输入原来属于不同模态，为什么最后可以计算余弦相似度？哪些知识是预训练模型提供的，哪些代码是本项目实现的？相似度为什么不是正确概率？

## 一个可交付的学习实验

1. 在 validation 中选 3–5 个查询，预先写下假设。例如：“加入颜色后，前五个结果中不符合颜色的图片会减少。”
2. 固定完整图库与模型，保存原句、改写句、参数和相关图片 ID。
3. 运行实验，记录实际成功与失败。不要只选成功截图。
4. 解释一例失败：是文本歧义、图片风格、属性看不清、标注不完整，还是模型忽略否定？给证据，无法确定就注明。
5. 固定参数后运行 test，导出报告。把自己的观察写入学习笔记并导出 Markdown。

## 推荐提交的展示材料

- 一张检索截图及为什么这样排名的解释。
- 一个实际对照结果表，附数据规模与配置。
- 至少两个失败案例，附查询和图片 ID。
- 一段说明你理解了什么、还不知道什么、下一步如何验证的笔记。

可以在作品描述中准确写：“搭建了本地 CPU 中文图文检索与诊断实验工具，学习了预训练双编码器、余弦检索、缓存、评估与否定查询的局限。”只有实际完成并理解后，再写自己完成的具体工作；不要写成从头训练了 CLIP 或取得标准基准最优结果。
